# Обработка аватара на Beget

На сайте включён PHP 8.2/8.3, исполнитель `proc_open`, `ffmpeg`, `ffprobe`, `timeout`; загрузка и тело запроса не менее 50 МБ. Проверка `GET /avatar-process.php?action=health` возвращает только доступность и лимиты. Публикация клиентской части останавливается до загрузки, если проверка не проходит.

Авторизованный пользователь отправляет исходник напрямую на Beget (максимум 50 MiB). Временный файл остаётся в приватном системном каталоге. FFmpeg строит JPEG-предпросмотр 800 px, на котором выбирают кадр. После подтверждения сервер создаёт мастер 1000 px, вариант 560 px и постер 560 px для анимации. Видео/GIF приводятся к MP4/H.264 с `yuv420p` и `faststart`; фотографии сохраняются в WebP. В опубликованной странице используется вариант 560 px; мастер доступен владельцу через экспорт данных.

Каждый запрос проверяет JWT через Supabase Auth. Перекодирование ограничено `timeout` 90 секунд; интерфейс может отменить запрос. Временные файлы удаляются по завершении и при следующем обращении, если им больше часа. Старые WebM-аватары продолжают показывать постер при ошибке воспроизведения. Файлы прежних профилей не переписываются.

Если PHP 8, FFmpeg или лимит загрузки отсутствуют, не переключать UI на серверный путь: предварительная проверка в `scripts/deploy.sh` блокирует выкладку. После подключения проверить на iPhone Safari JPEG/HEIC (если поддерживается FFmpeg), GIF и MP4; медленные/разорванные загрузки и отмену; файлы 49 и 51 MiB; вид 560 px на публичной странице и 1000 px в экспорте.
