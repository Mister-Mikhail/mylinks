# Обработка аватара на Beget

На сайте включён PHP 8.2/8.3, исполнитель `proc_open`, `ffmpeg`, `ffprobe`, `timeout`; загрузка и тело запроса не менее 50 МБ. Проверка `GET /avatar-process.php?action=health` возвращает только доступность и лимиты. Публикация клиентской части останавливается до загрузки, если проверка не проходит.

Авторизованный пользователь отправляет исходник напрямую на Beget (максимум 50 MiB). Временный файл остаётся в приватном системном каталоге. FFmpeg строит JPEG-предпросмотр 800 px, на котором выбирают кадр. После подтверждения сервер создаёт мастер 1000 px, вариант 560 px и постер 560 px для анимации. Видео/GIF приводятся к MP4/H.264 с `yuv420p` и `faststart`; фотографии сохраняются в WebP. В опубликованной странице используется вариант 560 px; мастер доступен владельцу через экспорт данных.

Каждый запрос проверяет JWT через Supabase Auth. Перекодирование ограничено `timeout` 90 секунд; интерфейс может отменить запрос. Временные файлы удаляются при закрытии редактора/успешном сохранении и при следующем обращении, если им больше часа. Старые WebM-аватары продолжают показывать постер при ошибке воспроизведения. Файлы прежних профилей не переписываются.

Если PHP 8, FFmpeg или лимит загрузки отсутствуют, не переключать UI на серверный путь: предварительная проверка в `scripts/deploy.sh` блокирует выкладку. После подключения проверить на iPhone Safari JPEG/HEIC (если поддерживается FFmpeg), GIF и MP4; медленные/разорванные загрузки и отмену; файлы 49 и 51 MiB; вид 560 px на публичной странице и 1000 px в экспорте.

## Форма `full` (4:5)

`avatar_shape` принимает `round`, `square` и `full`. Квадрат и его рамка кадрирования имеют нулевое скругление; обводка совпадает с кругом. `full` занимает отдельную строку по всей ширине профиля без рамки и скруглений. Размер в процентах хранится для возврата к кругу/квадрату, но не применяется к `full`.

Клиент передаёт в `avatar-process.php` параметр `aspect`: `1` для прежних форм, `0.8` для `full`. Сервер сохраняет исходную обработку, ограничение 50 МБ и MP4 H.264, но кодирует прямоугольник 560×700 или 1000×1250 для `full`. Выбор файла зависит от измеренной ширины аватара и DPR. Фото, GIF и видео используют одинаковый кадр. Старые запросы без `aspect` остаются квадратными.

Перед выпуском применить миграцию `20261030180400_full_width_avatar.sql` и обновить edge-функцию `admin-profile`. Миграция сохраняет логику и права текущих RPC; владелец и черновик онбординга сохраняют форму через `profiles` с прежними RLS. JSON-экспорт версии 1 передаёт `appearance.avatar_shape` без преобразования; перенос через действующие пути сохранения принимает `full`. Отдельного пользовательского интерфейса импорта в MVP нет.
